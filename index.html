Minimum Spanning Tree — Theory

Why laying cables is really a graph problem, and how MST solves it optimally.

Problem Statement

A campus has N buildings (computers / labs / hostels) that must all be connected to a single network. Laying a cable between any two buildings has a cost (proportional to distance, trenching, material). We must connect every building while laying the minimum total length of cable.

Model it as an undirected weighted graph G = (V, E) where vertices = buildings, edges = possible cable routes, and weight = cable cost. The answer is a Minimum Spanning Tree.

Key Definitions

  • Spanning Tree: A subgraph that connects all V vertices using exactly V − 1 edges with no cycles.
  • Minimum Spanning Tree (MST): A spanning tree whose sum of edge weights is the smallest possible.
  • Cut Property: For any cut of the graph, the minimum-weight edge crossing that cut belongs to some MST. → Prim's uses this.
  • Cycle Property: For any cycle, the maximum-weight edge in it is not in any MST. → Kruskal's uses this.

Why Not Just Connect Everything?

If we used all E edges, the network would contain cycles — redundant cables that cost money but add nothing to connectivity. An MST keeps exactly the V − 1 cheapest edges needed for full connectivity. Redundancy is only needed for fault tolerance, which is a different (Steiner / k-edge-connected) problem.

Real-World Applications

  • LAN / campus cabling — the exact problem this project solves.
  • Electrical power grid layout minimizing transmission line length.
  • Water & gas pipeline networks for a city.
  • Road / railway construction connecting towns at minimum cost.
  • Clustering in machine learning (single-linkage clustering = Kruskal's).
  • Network routing (Spanning Tree Protocol in Ethernet switches).
  • Image segmentation and circuit board wiring.

Algorithm Implementations

C++ implementations used in the visualizer logic.

Prim's Algorithm

Grows the MST one vertex at a time, always picking the cheapest edge that connects a vertex inside the tree to one outside.

// Prim's — Min Heap + Adjacency List
// Time: O(E log V)

int prim(int V, vector<vector<pair<int,int>>>& adj, int src) {
    priority_queue<pair<int,int>,
        vector<pair<int,int>>,
        greater<>> pq;              // {weight, node}

    vector<bool> inMST(V, false);
    pq.push({0, src});

    int totalCost = 0;

    while (!pq.empty()) {
        auto [w, u] = pq.top(); pq.pop();
        if (inMST[u]) continue;   // stale entry

        inMST[u]  = true;
        totalCost += w;              // cable laid

        for (auto& [v, wt] : adj[u])
            if (!inMST[v])
                pq.push({wt, v});
    }
    return totalCost;
}

Kruskal's Algorithm

Sorts all edges by weight and greedily accepts an edge if it doesn't form a cycle. Uses Union-Find (DSU) for fast cycle detection.

// Kruskal's — DSU + Sorting
// Time: O(E log E)

struct DSU {
    vector<int> p, r;
    DSU(int n): p(n), r(n,0) {
        iota(p.begin(), p.end(), 0);
    }
    int find(int x) {
        return p[x] == x ? x : p[x] = find(p[x]);
    }
    bool unite(int a, int b) {
        a = find(a); b = find(b);
        if (a == b) return false;   // cycle!
        if (r[a] < r[b]) swap(a, b);
        p[b] = a;
        if (r[a] == r[b]) r[a]++;
        return true;
    }
};

int kruskal(int V, vector<Edge>& edges) {
    sort(edges.begin(), edges.end(),
         [](Edge& a, Edge& b){ return a.w < b.w; });

    DSU dsu(V);
    int totalCost = 0, used = 0;

    for (auto& e : edges) {
        if (dsu.unite(e.u, e.v)) {
            totalCost += e.w;
            if (++used == V - 1) break;
        }
    }
    return totalCost;
}

Dry Run Example

Consider 4 buildings with cable costs: A–B = 1, B–C = 2, A–C = 3, C–D = 4.

Kruskal's: sort → A–B(1) ✅ accept, B–C(2) ✅ accept, A–C(3) ❌ reject (A,B,C already connected), C–D(4) ✅ accept. Total = 1 + 2 + 4 = 7, using 3 cables for 4 buildings.

Prim's (start at A): add A–B(1) → add B–C(2) → cheapest crossing edge from {A,B,C} is C–D(4) → total 7. Same MST, different order.

Prim's vs Kruskal's

Both are greedy algorithms that always produce a minimum spanning tree — but they get there differently.

Which One Should You Use?

For a real campus cable layout, the graph is usually sparse (each building connects to only a few nearby buildings), so Kruskal's is typically the practical choice. However, if the network is densely meshed (E ≈ V²), Prim's with a binary heap performs better.

In this project, both algorithms are implemented and produce the same total cable cost — only the order in which edges are selected differs. This is a consequence of the MST uniqueness theorem: if all edge weights are distinct, the MST is unique.

Project Conclusion

  • Network cable optimization maps directly onto the Minimum Spanning Tree problem.
  • Both Prim's and Kruskal's correctly find the optimal cable layout with a greedy approach.
  • The total cable cost is minimized while full connectivity is guaranteed.
  • For V buildings, exactly V − 1 cable links are required — no more, no less.
